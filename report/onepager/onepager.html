How Askmargin works

A plain-language explainer for a 5-minute read. NLP mini-project: a question-answering assistant for PDF documents.

In one sentence: you ask a question about a document, Askmargin finds the few passages most likely to contain the answer, answers from those passages only, and tells you which page it came from. If nothing relevant is found, it says so instead of guessing.

The problem it addresses

A language model that answers from memory can state false things with confidence (a hallucination), and it knows nothing about your private documents. Askmargin uses Retrieval-Augmented Generation (RAG): first retrieve evidence from the document, then generate an answer restricted to that evidence. The answer can then be checked against a page number.

The pipeline in six steps

1ReadExtract the PDF text page by page; fix broken hyphens and odd characters. Keep the page number.
2SplitCut each page into chunks of about 500 characters, at sentence ends, with one sentence of overlap.
3EmbedTurn each chunk into a list of 384 numbers (a vector) with the MiniLM model.
4SearchTurn the question into a vector too. Rank chunks by cosine similarity.
5AnswerPut the top 3 chunks in a prompt for FLAN-T5. Page citation comes from chunk metadata.
6RefuseIf the best similarity is below a threshold, answer "not found in the documents".

Steps 1 to 3 happen once per document. Steps 4 to 6 happen for every question.

Why numbers? Embeddings in one paragraph

Computers cannot compare meaning directly, so the embedding model converts text into a point in a 384-dimensional space, trained so that sentences with similar meaning land close together. "How many attention heads?" and a sentence about "multi-head attention" end up near each other even if they share few exact words. Closeness is measured by cosine similarity: the angle between two vectors. 1.0 means pointing the same way (very similar), values near 0 mean unrelated.

Two older, word-counting methods are used as baselines for comparison: TF-IDF and BM25 score a chunk by how many of the question's words it contains, weighting rare words more. They do not understand synonyms, which is the gap embeddings are meant to fill.

Search is done two ways that give the same answer: a NumPy matrix multiply (to show the maths) and FAISS, a library built for fast vector search.

How it was built, and how well it works

What was built

  • Python notebook (notebook/askmargin_rag.ipynb): the reference implementation of all six steps, with evaluation. Libraries: PyMuPDF (PDF text), NLTK (sentences, stop-words, lemmas), scikit-learn (TF-IDF), rank-bm25, sentence-transformers (MiniLM), FAISS, Hugging Face Transformers (FLAN-T5).
  • Live website (askmargin.vercel.app): the same retrieval idea running inside the browser with transformers.js. Answers are extractive (the best-matching sentences are shown), and nothing is uploaded; your PDF stays on your device.
  • Test data: four public papers (Attention Is All You Need, BERT, RAG, Sentence-BERT) so every result can be reproduced. 30 hand-written questions: 25 answerable from a paper, 5 not in any paper (to test refusal).

Design choices, briefly

  • Sentence-aware chunks instead of blind cuts, so an answer is not split in half. One sentence of overlap keeps context across boundaries.
  • Citation from metadata, not from the model. The page number is stored with each chunk, so it cannot be invented.
  • A model that must stay in context. The prompt tells FLAN-T5 to use only the supplied text, or say it does not know.
  • Several retrievers compared (TF-IDF, BM25, MiniLM, and a BM25+MiniLM hybrid) so the choice of embeddings is tested, not assumed.

How it is evaluated

  • Recall@k: for what share of questions does a correct chunk appear in the top k results?
  • MRR: average of 1 / (rank of the first correct chunk). 1.0 means the right chunk is always first.
  • Answer correct: the expected key phrase appears in the answer. Citation correct: the cited page really contains it.
  • Refusal: the threshold is chosen to best separate answerable from out-of-document questions by their top similarity.
  • Extra tests: chunk-size ablation (250, 500, 800, 1200 characters) and a look at every wrong answer.

Reading it: MiniLM alone was not the best. BM25 beat it on all three measures, and the best result came from combining the two. Meaning-based and word-based search miss different questions. Smaller chunks (250 characters) helped MiniLM (Recall@3 0.68, MRR 0.62).

Refusal: threshold 0.24. All 5 out-of-document questions were refused; none of the 25 answerable ones were wrongly refused.

End to end (FLAN-T5): 17 of 25 answers correct (68%); the cited page was correct for 52%; faithfulness (answer words found in the retrieved text) averaged 0.95.

One real observation from the example runs

For "How many parallel attention heads does the Transformer use?" the top two chunks (cosine 0.697 and 0.696) were about multi-head attention but did not contain the number 8, and the notebook's answer was "I don't know." Retrieval found the right topic and missed the right sentence. Citation accuracy (52%) is lower than answer accuracy (68%): some correct answers were not credited to a page that contains the answer string.

Honest limits

  • Small test set: 30 questions on 4 NLP papers. Results may not carry over to scanned PDFs, tables, other languages or other subjects.
  • Similarity is not truth. A high score means "on the same topic", not "contains the answer". A wrong but related passage can still be retrieved.
  • Fixed threshold. One cut-off is tuned on this question set; a different document collection may need a different value.
  • Small generator. FLAN-T5-base (250 M parameters) is weak at long or multi-part answers. The website skips it and shows extracted sentences instead, so website and notebook answers will differ.
  • Text PDFs only. No OCR; a scanned page with no text layer yields nothing.
